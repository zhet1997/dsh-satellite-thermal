# 0.2.0 会话工作台改造

日期：2026-10-08。迁移基线提交：`c365c56`，作者 `wangqn <wangqn@microsate.com>`。开发仓库：`D:\Codes\dsh-satellite-thermal`。

## 本次行为

- 使用 DSH 官方 `sidebarRightTabs` 与 `sidebar.right.pane.tab`，工作台在会话右侧打开，原生对话保留。会话归属通过服务端持久化，选区更新不会重新关联已经切换的项目；不再使用全局“上次项目”。
- 会话组装时获取当前绑定项目的有限摘要，作为用户角色的外部证据上下文；不同会话隔离，未绑定或不可用时不会读取另一个会话的缓存。
- 界面四页签、紧凑工具栏、内滚动参数表。移除首页宣传页、顶部大统计卡和重复说明。窄面板可切换三维/拓扑、收起属性。
- 重点/辅助资料分入口，资料解析在独立线程队列执行。辅助资料本地关键词和相邻行筛选，保留 PDF 页码与文本行号；助手按关键词分页读取相关片段。结构化表格仍按明确字段和唯一组件匹配。不是完整的 LLM 文档分析，关键词可能漏检。
- 已确认、估算、推导、缺失分开统计；连接统计仅表示已建关系的证据覆盖。原文、文本与提取记录可追溯。后台资料不能覆盖人工输入；工况在分析期间变化则保留现值与候选工况。
- 3D 与拓扑共用稳定组件色，默认点击 STEP 个体。真实 NX 温度顶点色保留。图节点简化、网格吸附，参数刷新保留布局；辐射无连线文字、低强调，不虚构两两辐射关系。
- 轨道与工况成为拓扑节点，在对象属性区编辑；没有独立的轨道页签。
- 参数表可直接编辑常用数字，工作上下温限显示 °C，来源显示资料/估算/用户输入。未提供工作温限不自动补值。
- 任意参数保存、文件导入、轨道计算、MCP 修改都不自动创建求解 run，包括旧客户端传入 autoRun=true。只在明确新增计算时冻结当前修订，原队列保留。
- 温度结果显示冻结输入的上下限，分别对低温和高温着色并给出超限幅度。单侧温限不声称双侧通过。

## 新建项目的调用关系与卡顿处理

浏览器 → 已登录 DSH 的 `/api/satellite-thermal/service/projects` 代理 → 8790 热服务 `/api/projects` → 保存空 `project.json`。创建项目不调用语言模型、CAD 或 NX。原问题是同一 Python 进程内的 OpenCascade 接触识别持有 GIL，阻塞 HTTP；0.1.1 已将原生几何处理移到带时限的子进程。

本次保留代理/请求超时和非堆叠轮询，将资料解析移出请求路径，轨道计算也移出全局存储锁。轨道结果落库时复核修订；计算期间有编辑则返回冲突，不覆盖新输入。新建项目失败会在弹窗显示错误。
