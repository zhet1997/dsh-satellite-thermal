# 卫星热建模插件：首版开发基线

确认日期：2026-10-07。用户已结束需求访谈，授权开始构建；未列细节参照原 Agent Web 或合理默认值。本文作为实现与验收基线，不能将“已规划”标为“已实现”。

## 交付形态

- 标准 npm DSH 插件，安装到兼容官方网页版 DSH 的既有 profile，与已有插件共存，不修改宿主源码。当前适配基线为 0.2.0-rc.2，其他版本必须另行验证。
- 插件含网页、Host 代理、MCP 和热建模 Skill。轻量服务独立部署，NX / Simcenter 运行在单独工作站，不塞入插件 runtime。
- 普通 STEP + 参数资料及几何插件交付 ZIP 均可独立进入。有效 STEP 为前提，首版不做修复，不自动删掉参与计算的组件。

## 工作流程与可核查性

1. Excel/CSV、Word、文字 PDF、JSON、聊天资料汇总为确定结构的标准参数，保留字段单位、来源、估值原因和影响。扫描件后续支持。
2. 缺失或明显异常值可自动估算并继续，不要求用户逐项批准。无法识别组件身份/真实对象引用不能用猜测掩盖。
3. 全程能查看和修改，默认自动推进。三个检查点分别是标准输入、实际 NX 模型与网格/条件、结果与异常。求解前可查看 NX 回读，源几何不能冒充网格。
4. 上游物理输入保存后冻结快照并创建新 run。旧 run 继续，新 run 排队；允许手动取消，运行中取消需执行端确认。结果不能覆盖新版本输入。
5. 图布局只影响展示，不改变几何或触发计算。

## 首版热物理与交互

- 稳态先行；设计接口预留瞬态、随时间变化的功耗与外热流。
- 混合实体与壳/二维薄板；壳厚度和表面方向必须明确。
- 实体导热、内热源、接触热阻、外热流、空间辐射、组件/表面间辐射，使用 NX 原生能力。
- 导热关系来自实际接触面或资料。未建模的支架、螺钉、垫片等路径不自动补建。
- 三维点选组件/面、表格与批量编辑、聊天编辑、可编辑热拓扑共用同一数据。拓扑支持新增/删除/修改关系、热源和边界。
- 轨道外热流复用原六方向算法，也可手工输入或导入。默认推荐环境最冷/最热时刻并解释依据，六向值必须取同一时刻；可手选时刻。不将该推荐称为瞬态温度极值。

## 输出与验证

网页及数据包包含实际可编辑 NX 工程、真实网格与条件、温度云图、组件温度统计、已有温限对应的检查、能量平衡、标准输入和 run 记录。正式排版报告后续做。

验证先覆盖可解析的导热/接触/辐射小算例，再用交接中的可用真实 STEP 走全链路。当前未指定人工 NX 对照工程。网络断连、缺许可、尚未支持的物理项必须明确显示，不能用示例温度补成功。
