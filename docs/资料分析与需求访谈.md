### 4.1 参数容错与自动重算

已确认的产品行为：

1. 参数问题以可见问题清单呈现，定位到受影响组件、接触或工况；可以补充、更正并重新计算。
2. 缺失或明显不合理的参数允许估算后继续。不得把“关键参数缺失必须人工确认后才能继续”当作默认规则。
3. 估算值及其影响需要显著可见；参数估算不应只藏在后台 assumptions 文件中。
4. 上游修改后自动创建新 run，后续流程使用新输入重算。

据此采用的实现约束：每个 run 保存固定输入快照和对应结果，记录参数原值、采用值、来源与处理原因；编辑不会改写已运行的数据，旧结果不会覆盖新参数对应的状态。相同输入的重复保存和运行自己的状态/结果写入不应循环触发新 run。下游重算可复用经验证仍适用的上游产物，但应保留来源对应关系。

Q11 已确认旧 run 继续，新 run 自动排队，允许手动取消。取消需要执行端确认，不能用停止网页监听代替。Q10 明确首版按 STEP 合理可用设计，不加入异常几何修复/排除组件流程；参数资料“不阻塞”不等于允许删减参与分析的组件。正常运行故障仍需明确状态和错误信息，不将未产出工件报告为成功。

瞬态是后续明确目标；首版不应把用户给出的时序数据未经说明直接折算为某个稳态工况。用户已确认可手工指定时间，默认按轨道外热流推荐冷/热两态，展示选择依据，每个工况六向载荷取同一时刻。该推荐描述环境载荷工况，不宣称为瞬态温度极值。

### 4.3 标准参数交接

用户强调“热参数应该输入随意，但是在确认环节有一个标准的确定的格式，来到下一个步骤能确认不会缺失参数”。据此，流程应先解析与匹配，再统一单位、检查、补全/估算，生成标准输入快照；后续步骤读取此快照。

确认页展示同一份标准输入；按此前已确认规则自动推进，并不增加强制人工批准。自动校验、人工复核与 NX 实际应用状态分开记录。

标准结构应覆盖身份/版本、实体或壳表达、材料与表面属性、功率、接触导热、相互辐射、环境与外热流、网格/求解设置、每项值的依据及预期施加清单。具体内容见 [标准热参数交接格式草案](./标准热参数交接格式草案.md)。

下一步不缺参数指所选建模/分析方式必需的信息完整且对象可定位；不要求为不适用项或未来瞬态字段伪造占位值。标准参数齐全、NX 已实际施加、结果满足工程要求分别判断。

## 5. 已提出的问题与回答

### Q1：首版闭环的终点

- A：生成可编辑工程热模型，包含几何、材料、网格、连接、载荷和边界；暂不求解。
- B：热建模 + 真实稳态求解 + 温度场与检查结果。
- C：热建模 + 稳态、瞬态/整轨热分析。
- D：只迁移网页热参数、工况、三维交互和标准数据输出。

回答与纠正：用户选择 A 后明确纠正“不是说求解以后再做，而是其中应该设置一些可见的，人工可核查的环节”。因此不得记录为“首版排除求解”。Q8 后续已明确首版稳态、以后必须支持瞬态。

### Q2：实际支持的建模/求解软件

- A：首版 NX/Simcenter，预留其他软件接口。
- B：首版同时实际支持 NX/Simcenter 和 COMSOL。
- C：先建立通用热模型和数据接口，不绑定工程软件。
- D：先核实用户可用软件和运行环境，再决定。

已选 A：NX/Simcenter 优先，预留其他求解器接口。

### Q3：“任意网页版”的安装含义

- A：任意兼容版本的官方 DSH 网页实例；可装进已有环境、与其他插件共存、不改宿主源码。
- B：允许插件独立启动自己的 DSH 网页实例，类似现有几何工作台。
- C：还要求嵌入非 DSH 网站，成为独立网页应用。

已选 A：官方 DSH 兼容实例内安装、共存，不修改宿主源码。

补充明确：重型工程软件不放入 runtime，可通过 Docker 服务或 MCP 远程连接。

### Q4：人工核查怎样控制流程

已选：全程可查看和修改，但默认自动继续；有问题才暂停。**未采用**“检查点默认等待人工批准”的推荐项。Q9 补充明确参数缺失或不合理可估算后继续，不能把此类问题一律设为暂停条件。

### Q5：首版核查环节

已选三处：①组件/材料/功耗/热连接等输入；②网格与实际施加的载荷、边界；③求解结果与异常。求解前必须看得到实际生成的模型。

### Q6：网页核查深度

已选：网页展示从 NX 回读的真实模型、网格和条件，支持定位检查；同时可下载原生工程。Q12 已补充要求三维点选赋值、参数表、批量与聊天编辑。

### Q7：输入与参数资料

已确认：普通 STEP＋热参数资料、几何插件交付包均支持。用户补充：“参数资料也要有一定的容错和补充和检查的机制，会标记出缺失或明显不合理的选项，并且不会卡住”。Q15 已确定资料格式和统一交接要求；合理性规则与组件匹配在实现设计中细化。

### Q8：稳态与瞬态

已确认：稳态和瞬态后期都必须支持，瞬态包含随时间变化的功耗和外热流；第一版先做稳态。Q19/Q20 指定按轨道外热流推荐冷/热两态并允许手动选择时间。

### Q9：估算与重新计算

已选 B：允许自动估算并继续，显著标出估值及影响，保留修改重算入口。用户补充：“做流程化，前部分修改了参数后，后续流程自动按照一个新的 run 来做重算”。未采用“关键未知参数必须暂停人工确认”的推荐项。

### Q10：异常几何边界

用户回答：“基本可以保证 step 合理可用，首版不考虑这个情况。”因此首版按可用 STEP 输入设计，不加入自动修复、组件排除或异常几何治理模块。没有授权原流程式的自动删减分析组件。

### Q11：旧 run 与新 run

已选：旧 run 继续，新 run 自动排队；允许手动取消旧 run。每个 run 保留自己的输入快照和结果，旧结果不能覆盖新参数对应状态。

### Q12：网页编辑

已选：表格和批量编辑＋三维点选组件/面设置材料、功耗、接触和边界；聊天也能修改。NX 内部人工编辑后回传合并尚未要求。

### Q13：首版热物理

已选：实体导热、发热、接触热阻、外热流、对空间辐射，以及设备/表面之间的辐射换热，使用 NX 原生能力。尚未将 MLI、热管、加热器等专用热控对象列为首版必需项。

### Q14：外热流来源

已选 A：支持手工输入、文件导入，并整合原项目六向轨道外热流计算。首版没有要求按实际几何、姿态和遮挡独立开发面级外热流计算器。

### Q15：参数资料格式与标准化

已选 A：Excel/CSV、Word、文字型 PDF、聊天文本和 JSON；扫描件后续支持。

用户补充：“热参数应该输入随意，但是在确认环节有一个标准的确定的格式，来到下一个步骤能确认不会缺失参数。”此要求与自动估算/默认推进一起生效，形成标准输入交接检查，不改变此前无须每步人工批准的约定。

### Q16：热拓扑直接编辑

用户先补充：“之前 web_agent 的设置完全是表格化的，最好这一版能有个可视化更强的热拓扑关系示意的界面，这里可以参考下其他开源项目。”

随后明确选择：可以在图上新增、删除、修改导热/接触/辐射关系，并编辑热源和边界；与三维和表格联动。该功能纳入首版。

### Q17：实体与壳模型

已选：首版必须支持实体与壳/二维薄板混合建模。不能沿用原 STEP 演示的全 TET4 实体方案作为全部首版能力。壳厚、法向、上下表面和实体/壳连接映射需进入标准模型信息。

### Q18：自动建立热关系

已选：依据实际接触面和资料建立导热连接，NX 计算表面间辐射；未建模的支架、螺钉等传热路径不自动补建。已知关系的参数可以按此前授权估算。

### Q19：稳态时间选择

用户回答：“可手动指定时间，默认时间是最冷最热态。”Q20 已明确采用轨道外热流推荐的冷/热时刻。

### Q20：默认冷热态选取

已选：根据轨道外热流自动推荐冷、热时刻，展示选择依据；六向载荷取各自选定的同一时刻。允许手工改时间。不要求首版先对多时刻逐一求解再寻找温度极值。

### Q21：验收基准

已选：先用可解析小算例核对导热、接触和辐射，再从交接资料选择可用真实案例验证完整流程；目前不指定人工 NX 对照工程。当前交接案例存在源几何缺陷记录，需实际核对并选择符合输入范围的副本/案例，不能默认所有历史 STEP 合格。

### Q22：结果交付

已选：首版提供网页结果与可下载数据包；正式排版报告后续做。基础包包括可编辑 NX 工程、真实网格/条件核查、温度云图、组件温度统计、有温限时的超温检查、能量平衡检查、标准输入及 run 记录。

## 6. 访谈收敛与开发阶段事项

22 个问题及用户补充已覆盖首版功能、自动化、物理范围、可视编辑、标准数据、run 调度和验收交付。整理后的基线见 [首版需求与开发边界](./首版需求与开发边界.md)。

开发阶段再通过实际环境核实和设计评审收敛：官方 DSH 兼容版本、NX/Simcenter 版本/模块/许可、执行端可用协议与取消能力、真实模型规模、壳模型映射及求解精度、具体字段与默认值、冷热推荐指标、页面布局与库版本。当前未运行工程验收，不能把这些事项写成已验证能力。

这些技术决策优先由源码和实际试验决定；若发现需要改变用户已确定的首版范围，再单独说明具体影响。
