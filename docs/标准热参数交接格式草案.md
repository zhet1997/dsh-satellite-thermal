# 标准热参数交接格式草案

日期：2026-10-07。用途：落实需求访谈中“输入灵活，在确认环节形成标准确定格式，下游不会缺参数”的要求。本文定义数据语义与交接检查，尚非已经实现或冻结的 JSON Schema。

## 1. 已确认的处理方式

1. 接收 Excel/CSV、Word、文字型 PDF、聊天文本及 JSON；扫描资料留待后续。
2. 保留原文件、原文位置和原值，自动提取并匹配到组件、表面、连接或工况。
3. 标记缺失、冲突、单位不明及明显不合理项。按用户授权补充或估算，显示采用值、依据和影响。
4. 在可见的确认环节形成完整、确定的标准输入，默认自动校验和继续，用户可查看并修改。
5. 后续建模读取该标准输入，不在各阶段重新猜测原始文档中的数值。
6. 每个 run 固定自己使用的标准输入和几何版本。上游修改产生新 run，旧 run 继续、新 run 排队，允许手动取消。

自动校验完成与人工已复核分别记录；界面不能将自动处理伪装成人工批准。

## 2. 标准输入的内容

下表是建议的数据分区。字段名和文件布局在实现设计中确定，但每项工程含义与完整性责任应保持明确。

| 分区 | 必须明确的内容 | 下游用途 |
|---|---|---|
| 版本与几何引用 | 格式版本、项目/输入修订、几何文件及内容摘要、坐标系、单位、稳定组件/表面身份 | 确保参数与实际几何对应，同一 run 不混入新版输入 |
| 分析工况 | 首版稳态、工况名称、功耗模式、外热流来源和归并方式、适用对象 | 固定本次求解的工程问题 |
| 模型表达 | 每个对象采用三维实体或壳/二维薄板；壳厚、法向、上下表面及偏置约定 | 支持用户已确认的实体/壳混合建模，避免两类表面或接触映射混淆 |
| 材料与表面 | 与所选模型相符的导热属性；参与辐射/吸收的表面光学参数及施加对象 | 建立真实 NX 材料和表面条件 |
| 发热 | 每个发热对象的确定功率/载荷表达、单位、位置及归属工况 | 避免把设备总功耗与体积热源数值混用 |
| 接触与导热关系 | 两侧组件/表面、连接类型、接触面积来源、热阻/热导定义与单位 | 明确 W/K、K/W 与 m²·K/W 等不同参数的转换依据 |
| 相互辐射 | 参与表面/腔体/分组及表面属性，计算方法和需要建立的 NX 对象 | 区分设备间辐射与对空间的辐射边界 |
| 环境与外热流 | 手工/导入/轨道计算来源，六向定义、坐标映射、具体受载面、入射/吸收量的语义、空间边界 | 防止方向错配或光学系数重复施加 |
| 网格与求解设置 | 实体/壳所需的有效网格与求解策略及明确参数 | 下游执行时不缺少所选建模方式必需的设置 |
| 值的依据与问题清单 | 原值、采用值、单位、出处、估算/推导方式、冲突处理、影响提示与人工修改记录 | 支持核查、修改、追溯和估值展示 |
| 预期施加清单 | 本次应创建的材料、网格对象、导热/接触、辐射、功率和边界对象及关联身份 | 与 NX 回读的实际状态逐项对照 |

温度限值、后续瞬态需要的密度/比热/时序等按所选分析模式决定是否必需。首版不能为了让所有字段看起来非空而填入无意义占位值。

## 3. “完整、确定”的检查

- 每个当前分析模式所必需的参数都有唯一采用值；不能传递空白、待定、NaN 或含义不明的文本给建模阶段。
- 类型、单位、数值范围和换算一致；保留原始表达，例如摄氏温度转换为内部温度单位时仍可查看原值。
- 每个材料、功率、连接和边界都有可定位的施加对象；组件名称相同不能作为唯一匹配依据。
- 资料冲突必须明确本次采用值并保留冲突记录。不得在不同阶段各自选用不同来源。
- 缺少值可按授权估算，但估算标记不因通过完整性检查而消失。零功率/零热流只能作为明确采用值存在，不能与缺失混为一谈。
- 不适用字段按当前模式标明不适用；与实际对象类型不符的字段不能直接忽略。
- 六向外热流必须说明方向、坐标与具体表面映射；入射与吸收功率的关系明确，避免太阳吸收率或红外发射率遗漏/重复作用。
- 网格、材料、接触与辐射设置都应对应同一几何和输入版本。
- 原始资料不完整时，补全/估算属于标准化阶段的工作；不能以不完整状态越过交接检查。若标准化程序自身失败，应明确报告失败原因，不能无限等待或伪造齐全状态。

## 4. 三种状态分别展示

| 状态 | 能说明什么 | 不能据此推断什么 |
|---|---|---|
| 原资料状态 | 哪些值来自资料，哪些缺失、冲突或异常 | 资料不完整不意味着必须阻止运行 |
| 标准输入状态 | 本次建模必需信息完整、单位与对象一致，可重复读取同一采用值 | 参数完整不能证明 NX 已经实际建立条件，也不能证明估值是实测值 |
| NX 实际应用状态 | 从 NX 回读到的实体/壳、网格、材料、连接及载荷，与标准输入是否一致 | 条件已施加不能单独证明温度达标或数值精度满足工程要求 |

确认页、参数表和热拓扑都应保留这些区别。模型实际应用、求解完成、结果检查也应分别有状态。

## 5. 首版外热流与未来瞬态

用户已确认首版支持手工输入、文件导入和原六向轨道外热流计算；首版稳态、后续必须瞬态。

Q19/Q20 已确认可手工指定时间，默认按轨道外热流推荐冷/热两态并展示依据；每个工况的六向值取自同一时刻。应保存推荐方法、时间与原始数据版本。不得把六个方向各自不同时刻的峰值拼接后称为实际同时发生的工况，也不将外热流推荐时刻宣称为真实瞬态温度极值。

后续瞬态扩展再加入时序、单位、时间基准、插值策略和初始条件等必需项。首版保留源时序与来源，并不代表已经支持瞬态求解。

## 6. 已确定边界与实现阶段事项

- Q18 已确认依据真实接触面与资料建立关系，不自动补建未建模支架、螺钉等路径；对已有关系估算热阻仍被允许。
- Q20 已确认默认按外热流推荐冷/热时刻；具体推荐指标在实现设计中给出，需可解释和覆盖。
- 标准输入实际 JSON Schema、来源字段优先级、缺省参数与合理性阈值由后续实现设计提出；应能展示、追溯和修订，无需把每个内部字段逐项变成访谈问题。

首版验收应覆盖：不同资料格式得到同一标准结构；缺失/异常数据经补全后可执行且估值标记保留；编辑后新 run 读取新快照；NX 实际应用与清单对应；混合实体/壳模型具有完整的表达信息。
