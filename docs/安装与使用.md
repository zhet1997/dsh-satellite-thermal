## 本机升级顺序

本次开发没有替你安装新版插件，也没有重启你的 3080 DSH 或 8790 热服务。

**0.2.0 插件必须配套 0.2.0 轻量热服务。** 旧服务没有会话绑定和异步资料接口。已连接的 NX 执行器可继续使用，本次不要求更换 NX 软件或重新安装 worker。

### 1. 在合适时机更新轻量热服务

先保存页面编辑内容，检查没有正在导入的文件。升级时会重启热服务；不要为了升级结束 NX 的工程进程。继续使用已有项目数据目录：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "D:\Codes\dsh-satellite-thermal\release\dsh-thermal-web-0.2.0\scripts\Start-LocalService.ps1" -Restart -DataDirectory "D:\AgentPrj\my_new_computer\work\dsh-satellite-thermal\release\dsh-thermal-web-0.1.0\runtime\thermal-projects"
```

该命令使用本机已配置的 WSL Ubuntu Python 环境，窗口应保持运行。`-Restart` 只处理指定端口的热服务，不结束 DSH 和 NX。若你已经另行更改项目数据目录，把 `-DataDirectory` 换成实际目录，避免启动出一个空项目库。

检查服务：

```powershell
Invoke-RestMethod http://127.0.0.1:8790/api/health
```

应显示 `version: 0.2.0`、`status: ok`。未连接 NX 时仍可整理资料和模型；求解需连接执行端。

### 2. 自己从 DSH 网页安装

打开 `http://127.0.0.1:3080/`，进入 **插件 → 添加插件**，填写 DSH 所在主机可以访问的完整路径：

```text
D:\Codes\dsh-satellite-thermal\dist\lbk-dsh-satellite-thermal-0.2.0.tgz
```

等待安装完成，刷新页面；若宿主提示需要重启，再重启已有 DSH 实例。不要同时在 3080 启动两个实例。安装后插件版本应是 `@lbk/dsh-satellite-thermal 0.2.0`。

如果网页安装失败，保留完整错误信息。常见原因是服务器看不到这个路径、pnpm 没有可用运行环境，或旧 DSH 不提供右侧标签页扩展。这个包没有发布到公共 npm，不能只填写包名让它从公共仓库下载。

可供你自行使用的命令行等价安装命令：

```powershell
& "C:\Users\49076\AppData\Roaming\npm\dsh.cmd" plugin --profile web add "D:\Codes\dsh-satellite-thermal\dist\lbk-dsh-satellite-thermal-0.2.0.tgz"
```

### 3. 检查热服务连接

在 DSH **设置 → 内置插件 → 卫星热建模** 中设置：

- 服务地址：`http://127.0.0.1:8790`。
- 令牌：沿用原配置；启用服务令牌的远程部署必须填写匹配令牌。
- 点击检查连接，确认热服务可达。

浏览器通过已登录的 DSH 代理访问服务，令牌不放进 iframe URL。

## 新界面的使用方式

1. 在一个 DSH 会话内，点击输入区 **热建模工作台**。工作台在右侧打开，左侧原生对话保留；可用宿主的分隔条调整宽度。极窄屏幕下 DSH 可能切换全屏显示，这是宿主布局行为。
2. **新建项目**，或从顶部下拉框明确关联已有项目。绑定保存在热服务中；不同会话默认不共享项目，明确选择同一项目即可协作。独立访问 `/satellite-thermal/` 时没有会话绑定，需手动选择项目。
3. **资料与几何**：导入 STEP/STP 或几何交付 ZIP。已筛选的参数和要求放“重点资料”；长报告放“辅助资料”。上传后后台分析，不必等待才能查看其他页面。原文件和提取文本可下载。
4. **热模型**：点击组件查看属性，三维和拓扑颜色对应；默认按 STEP 个体选中。拓扑吸附网格、保存排版，参数更新不重新排列。辐射连线默认弱化，可切换关系层。点击“轨道与环境”或具体工况节点，在对象属性区编辑；窄面板可切换三维/拓扑并收起属性。
5. **参数核查**：直接修改功耗、发射率、吸收率和工作温度上下限，离开输入框或按 Enter 保存；材料、壳参数等使用组件编辑窗口或批量编辑。显示资料/估算/用户输入来源。温限显示 °C、内部保存 K；未提供温限就留空。
6. **运行与结果**：此前的保存都只更新输入修订。选择全部工况或一个工况，点击 **基于当前修改新增计算**，创建固定输入快照并排队。旧运行继续，允许单独取消。重复提交同一活动输入会复用已有排队请求。
7. 查看本次 NX 实际模型、条件和温度。结果用本次冻结输入的工作温限检查，低温蓝色、高温红色，同时显示上下限和超限幅度。未设温限不会判为通过。

会话每次组装模型输入时，会获取当前绑定项目的修订、选区、资料摘要及状态。长资料默认只提供筛选摘要；助手可按关键词分页获取相关片段。点击工作台“对话”会把问题及选区放入左侧草稿，由你发送。

辅助资料筛选使用本地关键词及相邻行，PDF 片段保留页码；它不是完整的语义理解，可能漏检。结构化表格按精确组件名称/身份提取，未识别内容保留等待核查。自动分析不覆盖人工填写的参数；冲突需要在参数表或对话中处理。覆盖图反映证据/确认程度，估算值不充当已确认资料；连接评分只针对已建关系的依据，不保证物理路径齐全。

## 数据与部署

| 内容 | 位置 |
|---|---|
| 本机原有项目 | `D:\AgentPrj\my_new_computer\work\dsh-satellite-thermal\release\dsh-thermal-web-0.1.0\runtime\thermal-projects` |

移到其他电脑时解压完整安装套件，保留目录结构。可以通过 Docker 部署轻量服务：复制 `.env.example` 为 `.env`、配置 NX 远程端点和令牌，再执行 `docker compose up -d --build`。NX 位于远程工程工作站，不包含在轻量 runtime 中；DSH 必须能连接服务地址。Docker 与 WSL 本机方式二选一，不要抢占同一端口。

首次安装 Python/npm 依赖和 Docker 镜像可能需要网络，套件不是完全离线依赖包。NX 计算需要真实许可证。
