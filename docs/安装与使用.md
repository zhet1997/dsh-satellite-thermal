本机现有项目保存在旧套件的数据目录，升级后重启服务请明确沿用它：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "D:\AgentPrj\my_new_computer\work\dsh-satellite-thermal\release\dsh-thermal-web-0.1.1\scripts\Start-LocalService.ps1" -Restart -DataDirectory "D:\AgentPrj\my_new_computer\work\dsh-satellite-thermal\release\dsh-thermal-web-0.1.0\runtime\thermal-projects"
```

### 第三步：安装到日常 DSH 网页

**先确保启动 DSH 的环境能找到 pnpm。** DSH 的网页安装按钮也会调用主机上的 `pnpm`。仅 Codex 内置运行环境能找到它，不代表从桌面快捷方式打开的 DSH 也能使用它。在普通 PowerShell 窗口执行：

```powershell
pnpm.cmd --version
```

如果提示找不到命令，安装到 Node.js 的全局工具目录。**版本需匹配已有 DSH 配置，不能随意换一个主版本。** 本机 `web\node_modules\.modules.yaml` 的 `packageManager` 记录为 `pnpm@11.19.0`，对应命令是：

```powershell
npm.cmd install --global pnpm@11.19.0
```

本机该目录是 `C:\Users\49076\AppData\Roaming\npm`，已在 Windows 用户 PATH 中。其他电脑可以用 `npm.cmd prefix --global` 查看实际目录，并将该目录加入 Windows 用户 PATH。重新打开 PowerShell 验证 `pnpm.cmd --version`；若修改过 PATH，还需通过原有方式重启 DSH 及其启动器/监控脚本，让它们读取新环境。

其他 DSH 配置应先查看其 `node_modules/.modules.yaml` 中的 `packageManager`，采用记录的 pnpm 版本。安装脚本会读取这项记录，并在 pnpm 主版本不匹配时停止；无需删除现有 `node_modules` 或重新创建 profile。


套件还提供封装同一官方安装命令、检查 pnpm、校验包哈希并备份 profile 清单的脚本；如果 pnpm 仅来自 Codex 私有运行环境，脚本会在修改 profile 前提示修复：

## 3. 安装到另一台电脑或服务器

插件需装在运行官方 DSH 的主机；热服务和 NX 工作站可以分别部署。DSH 宿主需要 Node.js 22+ 和可用的 pnpm；已验证 DSH 版本为 0.2.0-rc.2。不要把本 npm 网页插件包当成 Electron 桌面安装程序。

1. 将安装套件复制到目标主机并解压。
2. 在 NX 工作站用 Python 3.10+ 安装套件中的 `.whl`。NX 本体另行安装并确保 Space Systems Thermal 许可可用。
3. 在 Linux/Docker 主机启动套件的轻量服务，设置可访问的 NX 工作站地址。
4. 用 DSH 的“添加插件”或 CLI 安装 `.tgz`，配置可访问的热服务地址。

### NX 工作站参数示例

可在工作站使用独立 Python 环境：

```powershell
python -m venv D:\ThermalWorker\.venv
D:\ThermalWorker\.venv\Scripts\python.exe -m pip install "D:\Tools\dsh-thermal-web-0.1.1\dsh_satellite_thermal_executor-0.1.0-py3-none-any.whl"
```

然后通过脚本指定该 Python、NX 路径和数据目录。仅本机连接时保持默认 `127.0.0.1`：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "D:\Tools\dsh-thermal-web-0.1.1\scripts\Start-NxWorker.ps1" -Python "D:\ThermalWorker\.venv\Scripts\python.exe" -NxJournal "D:\Install\NX12\NXBIN\run_journal.exe" -WorkRoot "D:\ThermalRuns"
```

需要从 Docker/Linux 或其他电脑连接时，在启动前设置 `NX_WORKER_TOKEN`，并给脚本加 `-ListenAddress 0.0.0.0`。服务端 `THERMAL_NX_WORKER_TOKEN` 必须相同。使用工作站实际可达的地址连接，不能将 `0.0.0.0` 当作目标地址。

### Docker 部署轻量服务

在安装套件根目录，将 `.env.example` 复制为 `.env`，配置示例如下；IP 和令牌需要替换：

```dotenv
THERMAL_NX_WORKER_URL=http://192.168.1.20:8791
THERMAL_NX_WORKER_TOKEN=填写NX执行器令牌
THERMAL_SERVICE_TOKEN=填写供DSH连接的热服务令牌
THERMAL_BIND_ADDRESS=127.0.0.1
THERMAL_PORT=8790
```

如果 DSH 与 Docker 服务不在同一台主机，把 `THERMAL_BIND_ADDRESS` 改为能被 DSH 主机访问的网卡地址或 `0.0.0.0`。在 DSH 设置中填写 Docker 主机实际地址，以及上面的 `THERMAL_SERVICE_TOKEN`。NX 令牌和热服务令牌是两段不同连接的凭据。

```sh
docker compose up -d --build
docker compose logs --tail 50 thermal
```

0.1.1 修复需要重新构建服务镜像，执行上述 `docker compose up -d --build`；旧 0.1.0 镜像不包含独立几何进程修复。Docker 部署和前述本机 WSL 直接启动二选一，避免占用同一个 8790。

**容器内 `127.0.0.1` 是容器自己**。连接 Windows NX 工作站应使用容器能访问的工作站 IP；本机原生 WSL Docker 不保证存在 Docker Desktop 的 `host.docker.internal` 名称。镜像不包含 NX。命名卷 `dsh-satellite-thermal_thermal-projects` 保存项目数据；查看 `docker volume inspect dsh-satellite-thermal_thermal-projects` 可确认实际挂载位置。

如果另一台 Windows 机器希望采用 WSL 直接运行，应先在 WSL 创建 Python 3.12 环境，安装 `service/requirements.txt` 及 CadQuery 所需系统库，再给 `Start-LocalService.ps1` 传入实际 `-Distribution` 和 `-Python`。默认的 `/home/zhet/...` 只适用于本机。

## 4. 网页怎样使用

1. **新建项目并导入几何。** 支持 `.step/.stp`，也支持几何插件交付 ZIP。可先打开明确标注的示例熟悉操作；示例没有伪造求解结果。
2. **导入热参数资料。** 支持 `.xlsx/.csv/.docx`、文字型 PDF、JSON 和粘贴文本。旧式 `.xls/.doc` 请先另存新格式；扫描 PDF 尚不支持。精确匹配组件的参数会应用，其余文字保留给助手处理。
3. **核对标准参数。** 橙色估值带来源和原因；缺失值按约定补齐，可修改。三维点选组件/面，在侧栏、表格或批量编辑中设置材料、功耗、接触和边界。
4. **编辑热拓扑。** 新增、删除或修改导热、接触和辐射关系，检查其绑定的实际组件/面。纯粹移动图上的节点位置不会触发重算。
5. **设置稳态工况。** 可手填六向外热流或计算轨道外热流，默认推荐冷/热时间点；每个工况的六向值来自同一时刻，也可手动选时刻。这不是瞬态最高/最低温度预测。
6. **保存并观察运行队列。** 自动运行开启时，物理输入变化会生成新版本和新 run。旧 run 继续，新 run 排队；可以取消。首次整理资料不想反复排队时，可暂时关闭项目“自动运行”，检查后手动开始。
7. **检查三个阶段。** 标准输入 → NX 真实模型/网格/条件 → 结果与异常。默认自动推进，无须逐项确认；仍可查看和修改。
8. **查看与下载。** 在运行页查看温度云图、组件温度、温限和能量平衡，下载 `.prt/.fem/.sim/.bun` 及项目数据包。上游修改产生新 run，旧工程不被覆盖。

从 DSH 聊天里的工作台使用 **交给助手**，可以输入例如：

> 检查当前项目缺少哪些材料和功耗信息，列出自动估值及其依据。
>
> 把选中组件的功耗改成 8 W，保留其他参数，并按新的修订重新计算。
>
> 对比这个项目的冷、热工况，说明最高温组件与能量平衡。

“交给助手”会先把项目和选区放进当前对话草稿，由你确认发送。单独打开的全屏工作台没有其父级聊天草稿接收器。

## 6. 常见情况

| 现象 | 检查方法 |
|---|---|
| 点击安装后立即失败，日志以 `'pnpm'` 开头，或提示“不是内部或外部命令”（中文可能乱码） | DSH 进程找不到 pnpm；按第三步在普通 PowerShell 安装与既有 profile 匹配的 pnpm，确认全局工具目录在 Windows PATH 中，再重试。Codex 终端中的 pnpm 可用不能单独证明网页宿主可用 |
| `ERR_PNPM_UNEXPECTED_STORE` | 先核对 profile 的 `node_modules/.modules.yaml` 中的 `packageManager` 和 `storeDir`；本机原依赖由 pnpm 11.19.0 安装，改用 pnpm 10 会发生此错误。安装匹配版本后重试；若版本已一致，再检查是否改过 pnpm store 路径，不要清空原配置和其他插件 |
| 安装时下载超时 | 插件包已在本机，但首次解析 npm 依赖仍可能联网；检查 DSH 主机的网络、代理和 pnpm，不要清空既有 profile |
| 没有热建模按钮 | 是否装到了当前运行的 profile；安装后是否重启并刷新；DSH 是否为适配版本 |
| 工作台提示未连接热服务 | 先打开 `http://127.0.0.1:8790/api/health`；检查服务窗口和地址，配置根地址不要加 `/api` |
