# 热拓扑界面：开源参考与首版方向

查阅日期：2026-10-07。状态：需求与技术选型参考，尚未制作界面或接入 NX。

## 用户已确认

旧 Agent Web 以表格设置为主，新插件需要可视化更强的热拓扑关系界面。用户进一步确认：可以在拓扑图上新增、删除、修改导热/接触/辐射关系，编辑热源和边界，与三维和表格联动。

已有统一规则继续适用：参数缺失或不合理可估算并显著标记；物理输入变更后创建新 run，旧 run 继续，新 run 排队；网页需展示 NX 实际回读的模型与条件。

## 2. 建议的热拓扑表达

以下是落实已确认需求的设计建议，详细视觉样式及布局尚未评审。

### 节点

- 默认按业务组件/舱板分组，显示名称、主要参数、估值/缺失标记和当前状态。
- 展开组件后定位实际参与连接或辐射的表面区域。
- 热源、规定温度、空间环境、外热流边界使用可区分的符号或卡片。
- 组件节点是工程视图中的聚合，不意味着该组件在有限元求解中被当作等温单节点；温度展示需标清最高、最低或平均值。

### 连接

- 导热/接触连接显示两侧实际组件及表面、面积、接触热阻或所用参数。
- 辐射显示参与表面或辐射腔体/分组。关系密集时按选中组件、相邻关系、分组展开，避免默认显示所有线。
- 外热流、发热及环境边界具有明确单位和实际施加对象。
- 未求解时主要表达传热关系，不能预先假定净热流方向。只有有可追溯结果时，才显示方向、线宽和热流数值。

### 状态

- 统一区分原始资料值、库值、推导值、估值与人工修改值，保留原值和采用原因。
- 同一视图可核对“当前编辑输入”和“选定 run 中 NX 实际建立的对象”，显示未生成、已回读、不一致或旧版本等状态。
- 每个已确认建立的节点/关系可追溯到组件/表面身份、输入版本和 NX 对象证据。
- 没有回读到的热流或条件显示未获得，不能用预期配置冒充实际结果。

## 3. 图、三维、表格、聊天怎样联动

1. 点击拓扑组件，三维定位并高亮该组件，表格显示同一对象的参数。
2. 点击热连接，三维高亮两侧表面，打开对应接触/辐射参数。
3. 三维点选或表格选择，拓扑自动定位相关节点与关系。
4. 在任一入口保存物理修改，都更新同一份工程输入，按已确认的 run 规则重新计算。
5. 对话修改使用相同的业务对象与修改接口；图形操作不应另建一套不可追溯的数据。
6. 拖动节点排版只改变视图，不移动 STEP 实体，也不触发求解。新增/删除热连接、修改参数才属于工程变更。
7. 在图上新增连接时绑定真实组件/面并选择连接类型；图形边必须能转换为有效的 NX 热对象，不能仅因画出一条线就标为已施加。

## 4. 首版界面验收建议

- 至少用一个含多个组件、接触导热、相互辐射、热源与空间边界的算例验证完整拓扑展示。
- 从图到三维、从三维到图均能定位实际对象；图、表格、聊天读取同一版本的数据。
- 从拓扑新增/删除一条热连接、修改一次热源，均形成新 run；NX 回读可验证变更已实际生效。
- 修改节点位置和折叠/展开分组不生成新 run。
- 估值、缺失信息和与 NX 不一致的条件可见，并能定位到对象。
- 求解后显示真实温度统计；热流或辐射交换量仅在取得可验证数据时展示。
- 切换历史 run 时，显示该 run 的拓扑、参数与结果，不能混入后来编辑的输入。

以上验收建议尚需纳入最终首版验收清单。Q14/Q15 已确认六向轨道计算＋手工/文件导入，资料支持表格、Word、文字 PDF、文本、JSON，并先形成完整确定的标准参数快照。Q17 另已确认实体/壳混合建模，拓扑和三维映射须能区分壳的两侧表面。
